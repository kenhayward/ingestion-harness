CT Studio release notes

Tuesday 27 October 2026: PDFs read for the first time, on the command line, then converted on the Conversion tab, each reviewed before it is delivered, scanned pages included; and a contract for administering a sink from CT Studio. PRs #338 to #342, #345 and #346.

Watch out for
  • The layout service now starts with the stack: the deploy scripts build and start it with the rest. The worker doesn't wait for it; a PDF that reaches it while it is down is retried. Its image is large (about 5.6 GB) and it may use up to 6 GB of memory. The compose profile pdf is gone; remove it from COMPOSE_PROFILES if you added it. With LAYOUT_URL empty, a PDF fails at once: "this CT Studio has no layout service (LAYOUT_URL)".
  • A database migration (202610271200_decomposition_review) adds the two new outcomes, Awaiting review and Rejected, each document's flag count, and the columns that record a held PDF and its review. It runs on its own when the API starts.
  • A PDF's decomposer version is the decomposer's version times 1000, plus the PDF reader's, so a newer PDF reader changes the version of PDFs without touching Word files, whose version stays 1. With scanned pages the reader is version 2, and with printed line and page numbers dropped it is version 3, so a PDF's decomposer version is now 1003 (it was 1001 earlier today, then 1002): a PDF run again is an ordinary update.
  • A PDF with a scanned page needs CT Studio's OCR model (Administration > Models, or ocr.model). Without one it fails at once: "page N is scanned and this CT Studio has no OCR model". Born-digital PDFs don't need it.
  • The delivery contract package is now 0.9.0, contract version 3. A sink may declare contractVersion: 3; it is still sent version 2 packages, and version 1 and 2 sinks are unchanged. Three new error codes: locked, forbidden and not_configured.

Minor changes

PDF reader, step 5a

#338

A born-digital PDF can now be decomposed into the same document a Word file gives. A new layout service finds the headings, tables and figures on each page, and the reader joins that with the PDF's own text. The same fidelity check as for Word then confirms that every word of the text layer ends up in the document, in the right block and the right table. Two new tools go with it: one decomposes a single PDF, the other scores a folder of Word files against their PDF twins.

The layout service is opt-in: it is not built or started unless the compose profile pdf is on (docker compose --profile pdf up -d layout). It parses untrusted PDFs, so it runs on an internal network with no route out.

Scored against the Word versions of four twin documents, headings were found with the right level in all 107 cases, 155 of 166 tables were found, 112 of those had the right shape, and 86% of cells were right. Word recall was 0.991 and precision 0.994. The weakest results are on small, borderless or heavily merged tables, and on extra tables. Two real PDFs with no bookmarks also decompose and pass the text check.

PDFs are not yet accepted on the Conversion tab. That comes in a later step, after the owner decides whether PDFs need review.

PDFs on the Conversion tab, with review

#342

The Conversion tab now takes Word or PDF files. A PDF is decomposed and checked as above, then held for review: nothing is delivered until someone approves it. A Word file goes straight through as before. Each line now shows how many flags its conversion raised, for Word files too.

A held PDF reads Awaiting review, and the Needs attention filter shows it. Review opens a page with the PDF's pages on the left and the document as it would be delivered on the right: its headings as an outline, each section's text, tables and figures, and each flag beside the part it is on. Choosing a heading, a part or a flag shows its page. Approve delivers exactly what was reviewed, with an optional note; Reject needs a note saying why, and is final. Anyone who may convert can review, including the person who started the batch.

A PDF is held only when its delivery would send something: one already loaded, a duplicate or one changed in the target gets that outcome at once, as a Word file does. If the target's document changes between the review and the approval, the approval sends nothing and says: "the target's document changed after this was reviewed; run it again". A rejected PDF is left out of Re-run failed; Force-load on its line reads it again and holds it for review again.

Scanned pages

#345

A PDF's scanned pages are now read too, so a scan, or a PDF with some scanned pages, can be converted on the Conversion tab. Each scanned page is sent to the OCR model CT Studio is already set up with, the same one, with the same settings, that extraction uses. Its headings, paragraphs, lists, tables and equations become part of the document, between the pages around it. Its pictures are cropped from the page, with the model's description of each.

A scanned page has no text of its own to check against, so it is flagged instead: every scanned page says it was read by the OCR model, and its tables are flagged too. The flags show on the batch line and on the review page, beside the page image. Like every PDF, a scanned one is held for review before anything is delivered.

A page counts as scanned when it has no visible text and is mostly image, or when one image covers at least 80% of it and it has no more than 20 visible words. The second rule catches a stamp or a page number printed over a scan; those words are left out and counted in the page's flag, and the OCR model reads them from the image anyway. A full-page figure with a short caption is read the same way, and flagged.

Each page's transcription is kept, so running the same PDF again reads the same text, and an extraction and a conversion of the same PDF share them. Scores for the OCR route, on the Word/PDF twins rendered as images, follow once they have been run against the OCR model.

Line numbers, page numbers and heading flags in PDFs

#346

Some guidelines print a running line number in the left margin of every line. The PDF reader kept those numbers as text, so a table's title read "2195 Table A1-7 …" and wasn't taken as its caption, the notes under a table weren't taken as notes, and paragraphs started with a number. They are now dropped as page furniture. Only a column of numbers left of all other text on the page, on at least half its lines and counting up, is taken for line numbers, so a numbered list or a table's first column of numbers stays.

A printed page number in a page's header or footer is now dropped on any page, whatever its form ("8", "A3 8", "Page 8 of 120"), even when it doesn't repeat on enough pages to count as a running footer, as an annex's own page numbers don't. When the layout analysis also took such a page number for a picture, the picture is dropped too, instead of being cropped to an image and flagged as a drawing. Both are counted in the dropped-text line of the report.

Every heading whose level was worked out rather than read from the PDF had its own "Heading level inferred" warning. On a real document that is nearly every heading, and the warnings hid the flags that need a reviewer's eye. They are now one information line at the top of the report: "Heading levels inferred for 34 headings".

Other updates

Delivery contract version 3

#341

The contract external sinks are built against gains an optional administration part. A sink that offers it lets a CT Studio administrator list, add, rename and remove the tenants it delivers to, and issue and revoke the access tokens its own callers use: each token limited to some tenants (or all), read-only or read/write, and expiring after 7, 30, 90 or 365 days or never. A token's secret is shown once, when it is issued. Tenants and tokens from the sink's own configuration are listed as locked. Every change names the administrator who made it, for the sink's audit log, which CT Studio can read back.

This is the contract and its conformance checks only; the administration page in CT Studio comes later.
