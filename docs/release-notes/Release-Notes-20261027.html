Minor changes

PDF reader, step 5a

#338

A born-digital PDF can now be decomposed into the same document a Word file gives. A new layout service finds the headings, tables and figures on each page, and the reader joins that with the PDF's own text. The same fidelity check as for Word then confirms that every word of the text layer ends up in the document, in the right block and the right table. Two new tools go with it: one decomposes a single PDF, the other scores a folder of Word files against their PDF twins.

The layout service is opt-in: it is not built or started unless the compose profile pdf is on (docker compose --profile pdf up -d layout). It parses untrusted PDFs, so it runs on an internal network with no route out.

Scored against the Word versions of four twin documents, headings were found with the right level in all 107 cases, 155 of 166 tables were found, 112 of those had the right shape, and 86% of cells were right. Word recall was 0.991 and precision 0.994. The weakest results are on small, borderless or heavily merged tables, and on extra tables. Two real PDFs with no bookmarks also decompose and pass the text check.

PDFs are not yet accepted on the Conversion tab. That comes in a later step, after the owner decides whether PDFs need review.

Other updates

Delivery contract version 3

#341

The contract external sinks are built against gains an optional administration part. A sink that offers it lets a CT Studio administrator list, add, rename and remove the tenants it delivers to, and issue and revoke the access tokens its own callers use: each token limited to some tenants (or all), read-only or read/write, and expiring after 7, 30, 90 or 365 days or never. A token's secret is shown once, when it is issued. Tenants and tokens from the sink's own configuration are listed as locked. Every change names the administrator who made it, for the sink's audit log, which CT Studio can read back.

This is the contract and its conformance checks only; the administration page in CT Studio comes later.
