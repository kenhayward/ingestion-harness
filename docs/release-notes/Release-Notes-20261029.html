CT Studio release notes

Thursday 29 October 2026: failed documents re-run in their own batch, which shows them going through, and an Auto approve choice when re-running. PR #361. Two more ICH guidelines read: PR #362, and four more: PR #363. Earlier batches can be deleted, and the target picked is remembered: PR #364. External targets take documents at their own pace, the groundwork for watched folders: PR #368. Documents to one target take turns: this PR.

Watch out for
  • The delivery contract is now version 4 (@ih/bridge-contract 0.11.0). Sinks built for version 2 or 3 keep working. An external sink that declares no lanes now gets one delivery at a time per tenant, and so does a sink that lists no instances, or a target with no instance: to take more at once, the sink declares an instance with lanes.
  • A new error code, destination_exists (needs a person): a watched-folder move whose destination already holds a different file. List answers may now carry any non-empty file name; requests still take one path segment of up to 255 characters.
  • Migration 202610291300_decomposition_lanes adds decomposition_items.lane_claimed_at, decomposition_batches.last_lane_at, publish_targets.lanes and the outcome waiting_to_deliver. Run the new API before the new worker: the API stamps each target's lanes from the bridge's sink list, and a target not stamped yet gets one lane.
  • Two new settings for the bridge: BRIDGE_DELIVERY_RUNNERS (delivery steps the bridge runs at once, 1 to 32, default 4; a delivery waiting on its sink holds none) and BRIDGE_MAX_SOURCE_MB (the largest file read from a watched folder, default 100). Both are optional.

Major changes

Documents to one target take turns

A target takes only so many documents at once, and a batch used to hand the bridge every document as soon as it was read, however long the queue there. Now a document asks for a free slot of its target before it is delivered; the worker reads the next document while the last one is delivered, and a document that finds no slot shows Waiting to deliver on its line, with the count in the batch's totals.

  • Batches to the same target take turns: when a slot frees, the batch that had one longest ago gets it, and within a batch the oldest waiting document goes first.
  • Nothing needs doing for a waiting document: it moves on by itself, within a few seconds of a slot freeing.

Minor changes

Re-running failed documents in their batch

#361

Re-running failed documents used to make a new batch and open it, so the batch they failed in went on showing them as failed, and it was hard to tell which of its documents had since gone through. Now they run again in the same batch: each failed line goes back to Queued and moves on as it runs, and you stay on the batch, which refreshes every few seconds while they are under way.

  • Re-run Failures is on the list's bar, after Find a document, when the batch has failed documents to re-run. It opens the same dialog as before, every failed document ticked. Re-run this document on the panel, and Re-run in a line's menu, do the same for one document, and also stay on the batch.
  • The dialog has an Auto approve switch under Keep Force-load. It starts off whatever the batch was started with: tick it to deliver the re-run PDFs without holding them for review.
  • A document can be re-run in its batch as often as it fails. A line's last failure reason and report are replaced by the new run's.
  • Documents re-run before this change, in a batch of their own, still say Re-run in batch and are re-run from that batch. So are documents run again by Force-load, Redeliver or Load as a new document, which still make a batch of their own.

Deleting an earlier batch

#364

Earlier batches add up over time. Each line of Earlier batches on the Conversion tab now ends with a bin that deletes the batch, once you confirm.

  • The batch leaves the list with its uploaded files and reports. The documents it delivered stay in the target, and are still found there when loaded again.
  • The bin is off while any of the batch's documents is still queued, converting, delivering or waiting for review; hover over it to see how many. Approve or reject held PDFs first.
  • A batch that was never started is discarded as before. A file a later batch still uses, such as a force-load re-run's, is kept until that batch goes too.

The Conversion tab keeps your target

#364

Coming back to the Conversion tab used to start a new batch on the first target in the list, whichever you had used last, so it was easy to load into the wrong one. The target you pick is now remembered in this browser, and a new batch starts on it for as long as it is still listed.

PDFs with a few words not proven are reviewed, not failed

#367

Every word of a PDF is checked against the page it came from, and a PDF with even one word that didn't match used to fail ("page 79: '1' extra"). Now a PDF with a few such words is held for review instead, so you decide.

  • Its line on the batch says how many words the check could not prove, and the first: The check could not prove 2 words: page 79: '1' extra (and 1 more). Its report lists each one.
  • Review lists them above the document. Choose one to see its page and compare it: approving delivers the document as it is shown.
  • It is held for review even in a batch with Auto Approve on.
  • More than 25 such words still fail the PDF: that many means a page was read badly. Any other failure, and a Word document's check, still fail as before.
  • The words are not sent to the target with the document.

Fixes

ICH S5(R3) and S11 read

#362

Two PDFs still failed after the last fixes. Once this is deployed, re-run them.

  • S5(R3) failed with 'C' missing. Its fonts are all set at 1 point with the size given by how the text is scaled, so the reader took its text for 1-point type and read subscripts, such as the "max" of Cmax, as lines of their own. Text is now read at the size it is printed. On the same document, two table columns drawn one after the other ran their words together on a line ("datagestation"); words side by side with a gap between them now get a space even when they were drawn apart.
  • S11 failed with 'Neonate' moved out of table. The layout analysis gave Appendix A's table of age bars both as a table and as a picture, with the table's text belonging to the picture. The picture was dropped but its text kept, so the table's cells came out empty. Now that text goes too and the cells get their words. A bullet in a wide cell also now stays in that cell, rather than going to the cell beside it.
  • Reading text at its printed size also finds subscripts and superscripts it used to miss: the "+" of Na+ in S7B, and the Cmax and IC50 of S10. Some paragraphs that had been split a word at a time (in S4 and S6(R1), say) now read whole.
  • Other PDFs can read slightly differently where their text is scaled, so their decomposer version changes (1009).

ICH S5(R3), S11, E2C(R2) and M9 delivered

#363

With #362, S5(R3) and S11 passed the reader's checks but were refused on delivery, each for the shape of a table read from its ruling lines. E2C(R2) and M9 failed in a run over the ICH guidelines. Once this is deployed, re-run all four.

  • S5(R3) was refused with row 3 has no cells. The underlines in its annex tables' cells ("aspirin", "salicylate") were taken for the lines between rows, so a table of one header row and one row of findings came out with a dozen rows, every cell spanning them all. A line now makes a row only where it is a cell's edge. Two of those tables, left as pictures before, are now read as tables.
  • S11 was refused with spans from the header rows into the body. The line under Table A1's header was drawn in three pieces at very slightly different heights, and the pieces were joined wrongly, losing the line under the first three columns. "Cardiovascular" was read into the header's "Age Categories" cell. The pieces are now joined along the line, and the header reads as drawn.
  • E2C(R2) failed with 'Shading' missing. Figure 1's drawing holds a second copy of its caption that is hidden (clipped away), on the same line as the one printed, and the two were read into each other a letter at a time. Hidden text is now left out.
  • M9 failed with '1' missing, at its f2 formula: the "t=1" under the sum and the "n" over it were one word to the document and two to the check. The check now reads them as one word.
  • The decomposer version changes (1010).

A clinical study protocol read

#366

The first clinical study protocol loaded (NCT03254108) failed with page 79: '1' extra. Once this is deployed, re-run it.

  • Its list of pharmacokinetic parameters has, on one line, subscripts (Cmax, AUC24h, t1/2,z) and raised table keys (#1). Together they spread the line further than the reader allowed for one line, so the subscripts were read as a line of their own after it. A line is now measured from its main text, and keeps both.
  • Behind that, its list of abbreviations would have failed with 'Abbreviation' moved out of table. The layout analysis gave the table's header row, "Abbreviation Definition", as a heading above the table. A line like that, just above a table and lined up with its columns, now becomes the table's header row.
  • The decomposer version changes (1011).

Other updates

External targets take documents at their own pace

#368

An external target can now say how many documents it can take at once, for each of its tenants. The bridge sends no more than that, however many documents are waiting for other targets, and a target that says nothing gets one at a time. The built-in targets are not limited.

This also prepares the ground for watched folders: a target can offer folders that CT Studio reads documents from and moves them out of once they are handled. Nothing uses them yet.
