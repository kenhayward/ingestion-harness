# API docs PR 1: infrastructure, public docs browser, Health and Auth

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a public OpenAPI 3.1 document and Scalar docs browser from the API, generated from
route `schema` blocks, with tests that keep the docs true, Health and Auth documented, and links
from the app.

**Architecture:** `@fastify/swagger` collects route schemas (Zod 3 converted with
`zod-to-json-schema` in a swagger `transform`); pass-through validator and serializer compilers
keep runtime behaviour identical. Scalar (`@scalar/fastify-api-reference`) is registered in its own
encapsulated context whose `onRoute` hook marks its routes `config.public`; the access hook reads
that flag instead of a path list.

**Tech Stack:** Fastify 5, `@fastify/swagger` 9.9, `@scalar/fastify-api-reference` 1.74,
`zod-to-json-schema` 3.25 (Zod 3.25.76), Ajv 8, `@apidevtools/swagger-parser` 13, Vitest,
React + Testing Library.

**Spec:** [docs/design/api-docs.md](../../design/api-docs.md)

## Global Constraints

- No runtime behaviour change: handlers keep `safeParse` and their exact error messages; response
  schemas never drop fields.
- Public routes are exactly `POST /api/auth/login`, `POST /api/auth/logout`, and the routes the
  docs plugin registers under `/api/docs` (plus `/healthz`, `/readyz`, which are outside `/api`).
- The access hook still decides on the matched route, never the raw URL.
- The OpenAPI document carries no deployment details: `servers: [{ url: '/' }]`.
- Tests never touch the network; TypeScript is ESM with `.js` import suffixes.
- `npm run check` green before the PR.

## Review Focus

1. A signed-out reader opens `/api/docs/` and the JS asset: both 200 (Task 2 test).
2. A request body that fails a route's documented schema still reaches the handler and gets the
   handler's own 400 message (Task 1 test).
3. A handler returning a field the response schema does not list still sends it (Task 1 test).
4. A documented route answers with a status code it does not document: the conformance check
   fails the test run (Task 3 test).
5. An encoded docs path (`/api/%64ocs/openapi.json`) is matched by the router like any other path
   and is public only because the matched route is a docs route; encoded guarded paths stay 401
   (existing path-handling tests in `access.test.ts` keep passing; Task 2 adds the docs case).

### Task 4: document Health and Auth

**Files:**
- Modify: `apps/api/src/routes/health.ts`, `apps/api/src/access/routes.ts`,
  `apps/api/test/openapi.test.ts` (shrink `UNDOCUMENTED`), `docs/openapi.json`

Routes and what each description covers:
- `GET /healthz` (Health): liveness, no dependencies checked, always `{ status: 'ok' }`.
- `GET /readyz` (Health): checks Postgres and the inbox bucket; 200 `ok` or 503 `degraded` with
  per-check messages.
- `POST /api/auth/login` (Auth & sessions): token body, sets `ih_session` (HttpOnly,
  SameSite=Strict, Secure over HTTPS, lifetime to token expiry, max 400 days; idle sessions end
  after 7 days); 401 invalid/expired; 429 rate limit per client IP.
- `POST /api/auth/logout`: ends the session, clears the cookie, 204 even without one.
- `GET /api/auth/me`: the signed-in token's role, label, expiry.
- `GET/POST /api/auth/tokens`, `POST /api/auth/tokens/:id/revoke`, `DELETE /api/auth/tokens/:id`
  (Access tokens, `x-admin: true`): list with statuses; create (plaintext shown once, expiry
  choices 1/7/30/90/365/never); revoke ends sessions and keeps the row; delete removes it; 409 for
  the admin token; 404 unknown id.

- [ ] **Step 1:** remove these routes from `UNDOCUMENTED` → sweep fails.
- [ ] **Step 2:** add schemas (`AccessTokenSchema`, `SessionViewSchema`, `CreatedTokenSchema`
  with a type-equality test against `AccessToken`) and descriptions.
- [ ] **Step 3:** `npm run openapi`; `npx vitest run --project api` passes (conformance now
  checks every auth/health response in `access.test.ts`).
- [ ] **Step 4:** commit `api: document Health and Auth routes`.
