# API docs PR 4: Workbench projects, samples, brief, test runs and bundles

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Document the first 18 Workbench routes: Projects & data policy, Samples & brief, Test
runs, Bundles. (PR 5 covers drafting, evaluation, feedback, holdout and publish, the S3 keys, and
deletes the allow-list.)

**Architecture:** As PRs 1–3: route `schema` blocks (documentation only), the docs sweep and the
response conformance hook; view interfaces in `@ih/shared` become Zod schemas with `z.infer`
types of the same name.

**Tech Stack:** as PR 1.

**Spec:** [docs/design/api-docs.md](../../design/api-docs.md)

## Global Constraints

- No runtime behaviour change; handlers and error messages untouched.
- Every status code a handler can send is documented with its exact message.
- `PUT …/data-policy` is admin-only (`x-admin: true`); the bundle routes' 403 for local-only
  projects is a different rule (data policy) and is described, not flagged.
- The holdout rule (only dev samples leave the harness) is stated wherever it applies.

## Review Focus

1. Sample upload: `role` field before the file, 400/409/413/415 and the 12-sample limit.
2. `GET …/samples/{sid}/text` is a 409 until the sample is ready.
3. Brief save answers 200 when unchanged and 201 with a new version otherwise.
4. Bundle download: 403 for local-only projects without the admin token, 409 when a carried
   sample is no longer a dev sample, 409 while the export runs.
5. Bundle import: field order (`id`, `name` before the file), 409 for an existing id, 500 after
   the project exists (delete and import again).
