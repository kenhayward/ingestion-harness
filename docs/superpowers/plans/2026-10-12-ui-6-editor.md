# UI redesign PR 6: Document type editor. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the document type editor as the handoff draws it:
- a header with an unsaved indicator, export, a ⋯ menu holding Delete draft, a **Publish vN** that explains why it's disabled, and **Save draft**;
- tabs with counts;
- pipeline steps as collapsible cards (one open at a time) with a one-line summary;
- a **Test this draft** rail with recent test runs.

**Architecture:**
- **Pure logic** goes in `apps/web/src/templates/editor-derive.ts`: `publishBlocker`, `tabCounts`, `stepSummary` and `recentTestRuns`.
- **`TemplateEditor` keeps all editing state.** The header becomes `EditorHeader` and the rail `TestRail`. The pipeline tab renders `StepCard`s around the existing `ExtractStep` and `CheckStep` bodies.
- **Data:** `App` passes the shell's polled `jobs` for the rail. `listTemplates` (already used by the Quality diff) supplies "from published vM".
- **No API changes.**

**Tech Stack:** React 19, Vitest.

**Spec:** `docs/design/ui-redesign/SPEC.md` §5, `FEATURES_AND_API.md` rows 20–22 and 24. Screenshot: the handoff's `05-editor-pipeline.png`.

## Global Constraints

- **Header:**
  - a back link "‹ Document types";
  - the H1 name, then a pill: "Draft vN" (info) or "Published vN" (ok);
  - a sub-line: "from published vM · <id>" for a draft with a published version, otherwise just "<id>".
  - **Right side, in order:**
    1. "Unsaved changes" with an amber dot, only when dirty;
    2. an Export YAML icon link (`aria-label="Export YAML"`);
    3. a ⋯ menu (`aria-label="More actions"`) for drafts, with "Delete draft" and an inline confirm ("Delete draft vN? This cannot be undone." with **Delete draft vN** and **Keep**);
    4. **Publish vN**, disabled with a `title` and a visible reason: "Save the draft before publishing" or "Fix N validation issue(s)";
    5. **Save draft** (primary).
  - **Published versions:** only **New draft from vN** and Export.
- **Tabs (underline):** "General", "Sections <n>", "Outputs <fields> · <tables>", "Pipeline <steps>", "YAML" and "Quality", with `role=tablist` / `tab` / `aria-selected`.
- **Pipeline step card:**
  - **Header:** a `button` with `aria-expanded`, showing the number badge, a kind tag (EXTRACT / CHECK), the id (mono) and the summary line, plus move up / move down / remove icon buttons with the existing `aria-label`s.
  - **Expanding:** only one card is open at a time, and the open card gets an accent border. Adding a step opens it.
  - **Body:** the existing step body, inside `role=group` named "Step N". "Fills" becomes a `Segmented` (Fields | A table).
- **Summaries:**
  - **Extract, fields:** "<n> fields · reads <sections> · <model or 'default model'>".
  - **Extract, table:** "Table <id> · <k> pages per call · <model>". The chunk part is omitted when unset.
  - **Check:** "<values> vs <reference>".
- **Test this draft rail** (`aside aria-label="Test this draft"`):
  - a drop zone with "Sample PDF" (a file input, PDFs only), hint "Test runs are reviewable but never published";
  - the primary button "Run test on <file>" once a file is chosen, else a disabled "Run test";
  - "Recent test runs": the newest 5 jobs with `test` and `specId === templateId`, excluding regression runs (`referenceId`). Each row has a file link to `#/review/<id>`, a relative time and a status pill.
- **General tab:** keeps the vertical labels-left layout the user asked for in PR #12. It is not changed to two columns.
- **Kept:** Quality tab behaviour (restyled by CSS only), the YAML tab, and the Sections and Outputs grids, with icon buttons for move and remove.

## Review Focus

1. **Publishing a draft with unsaved changes and issues at the same time.** The blocker names the first reason (save), and the button stays disabled until both clear. Test in Task 1.
2. **Removing the open step, or moving it.** The open card follows the step, or closes, and never points at another step. Test in Task 3.
3. **Delete draft confirm, then Keep.** Nothing is deleted and focus returns to the ⋯ button. Test in Task 2.
4. **Choosing a non-PDF in the rail.** It isn't accepted and the run button stays disabled. Test in Task 4.
5. **A draft with no published version.** There's no "from published" line, and Publish still works. Test in Task 2.

- [ ] **Step 1: Write the failing table tests**

  `publishBlocker`:

  | dirty | issues | Result |
  |---|---|---|
  | true | 2 | "Save the draft before publishing" |
  | false | 1 | "Fix 1 validation issue" |

  `stepSummary`:

  | Step | Result |
  |---|---|
  | fields step `{fields: [a, b], sections: [header, supplier]}` | "2 fields · reads header, supplier · default model" |
  | the same with `model: 'local/x'` | "… · local/x" |
  | table step `{table: 'lines', chunkPages: 2, model: 'm'}` | "Table lines · 2 pages per call · m" |
  | table step without `chunkPages` | "Table lines · default model" |
  | a step with 1 field | "1 field · …" |
  | check `{values: 'lines.batch', reference: 'header.batches'}` | "lines.batch vs header.batches" |
  | check with blank values | "not set up yet" |
  | unknown type | "" |

  `recentTestRuns`:
  - the type filter;
  - `test` true only;
  - regression jobs excluded;
  - newest first;
  - at most 5.
