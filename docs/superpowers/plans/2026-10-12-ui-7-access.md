# UI redesign PR 7: Access page. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the Access page as the handoff draws it:
- expiry presets as one-click buttons;
- a "The admin token rotates" note;
- a new-token panel that is easy to copy from;
- status filter chips with counts;
- expiry shown as a date plus a relative time, amber when the token expires within 7 days;
- status pills;
- the existing inline confirms, reworded.

**Architecture:**
- **Pure logic:** `apps/web/src/access/derive.ts` holds `tokenGroup`, `tokenCounts`, `expiresSoon` and `expiryText`.
- **Components:** `AccessPage` is reworked in place, keeping `NewToken` and `TokenActions`.
- **No API change:** `listTokens` already returns `status` and `expiresAt`.

**Spec:** `docs/design/ui-redesign/SPEC.md` §6, `FEATURES_AND_API.md` rows 25–26. Screenshot: the handoff's `06-access.png`.

## Global Constraints

- **Header:** "Access" + "People sign in with an access token. Issue a token per person or machine; revoking one ends its sessions immediately."
- **Issue a token** (a form labelled "Issue a token"):
  - **Label:** `maxLength` 100, placeholder "e.g. Ken – laptop".
  - **Expires after:** a `Segmented` group with 1 day / 7 days / **30 days** (default) / 90 days / 1 year / Never.
  - **Create token** button.
  - **Side note:** "The admin token rotates", explaining the admin token in the API log.
- **New token panel** (`role=region`, named "New token"):
  - "Token created for “<label>”" and "Copy it now — this is the only time it will be shown.";
  - a read-only mono input named "New token for <label>", which selects on focus;
  - **Copy** (shows "Copied" after success) and **Done**;
  - the existing status line with the HTTPS clipboard fallback text.
- **Chips:** All · Active (including the current admin) · Expired · Revoked, each with a count.
- **List** (columns Label · Role · Created · Expires · Last used · Status · Actions):
  - **Role** is a tag: admin = info, user = neutral.
  - **Expires** shows the date plus a relative time ("in 2 days" / "6 weeks ago"), "Never", or "On restart" for the current admin. It is amber 600 when the token expires within 7 days.
  - **Expired and revoked rows** are muted.
  - **Status pills:** Active (ok), Expired (neutral), Revoked (danger), Current admin (info).
  - **Actions** (user tokens only): **Revoke** (active only), plus an icon button named "Delete <label>". The current admin row shows "Rotates on restart".
- **Confirms:**
  - The row turns danger-tinted, and the label's sub-line reads "Revoke? Its sessions end now." or "Delete this token record?".
  - The buttons are **Keep** and **Revoke now** / **Delete**, with the confirm button in danger fill and focused.
  - Keep sends nothing.
- **Search:** the top-bar search still filters, including the "No tokens match" row. Non-admins see "Admins only.".

## Review Focus

1. **A token expiring in less than a day, or already past `expiresAt` but not yet marked expired by the server.** The text reads "today" / "in 5 h", amber; a past time reads "… ago". Test in Task 1.
2. **A chip with no matches, combined with the search.** The table shows "No tokens match …" or "No tokens in this view.". Test in Task 2.
3. **Copy fails or the clipboard is missing.** The fallback text shows, and "Copied" never appears. Test in Task 2.
4. **The current admin token.** It never gets Revoke or Delete. Test in Task 2.
5. **Keep after Revoke.** Nothing is sent. Test in Task 2.
