# UI redesign PR 2: Jobs page. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Jobs page as the handoff draws it:
- an upload strip that takes several files at once;
- filter chips with counts and a live indicator;
- a job list with one main action per status and a ⋯ menu for the rest;
- a detail panel with a progress list, outputs and actions;
- a card layout on phones.

**Architecture:**
- **Pure logic:** derived values (labels, tones, the main action, the context note, chip groups, the progress list, relative time) live as pure functions in `apps/web/src/jobs/derive.ts`.
- **Components:** the list, row actions, detail panel and upload strip are separate components in `apps/web/src/jobs/`. `JobsPage` composes them, and `App.tsx` renders it.
- **API:** one small addition, `GET /api/jobs/:id/document`, which streams the uploaded PDF for "Open PDF". It is TS-only: no worker or contract change.

**Tech Stack:** React 19, Vitest + Testing Library, Fastify 5 (`app.inject`), Postgres (`PgRepo`).

**Spec:** `docs/design/ui-redesign/SPEC.md` §1 (Jobs), `FEATURES_AND_API.md` rows 3–8 and the "Derived client logic" table. Visual reference: the handoff's `screenshots/{light,dark}/01-jobs*.png` (scratchpad copy).

## Global Constraints

- **Status labels and tones:**

  | Status | Label | Tone |
  |---|---|---|
  | `queued` | Queued | neutral |
  | `running` | Running | info |
  | `awaiting_review` | Awaiting review | warn |
  | `needs_review` | Needs review | alert |
  | `failed` | Failed | danger |
  | `succeeded` | Succeeded | ok |
  | `rejected` | Rejected | neutral |
  | `cancelled` | Cancelled | neutral |

- **Main action per status:**

  | Status | Main action |
  |---|---|
  | `awaiting_review` | **Review** (link, filled accent) |
  | `succeeded` | **View** (link) |
  | `failed`, `needs_review`, `cancelled` | **Retry**, using the upload strip's model |
  | `queued`, `running` | **Cancel** (inline confirm) |
  | `rejected` | none |

- **Chips:** All, Needs attention (awaiting_review, needs_review, failed), In progress (queued, running), Finished (succeeded, rejected, cancelled). Each shows a count, and the Needs attention count is always amber. The group is `role=group`, `aria-label="Filter jobs by status"`, and each chip uses `aria-pressed`.
- **Accessible names:**
  - Document cell button: "Show details for <file>".
  - Menu button: "More actions for <file>".
  - Detail panel: an `aside` named "Job details".
  - Upload form: "Upload document".
- **Destructive actions** (Delete, Cancel, Re-process) keep the inline confirm. The existing names stay: "Confirm <action> <file>" / "Keep <file>". Focus moves to Confirm, then back to the opener.
- **Retry:** uses the upload strip's model (`ih.uploadModel`) and the latest template version, as today. "Retry with another model…" picks a different one inline.
- **Re-process for succeeded jobs** (existing feature) lives in the ⋯ menu.
- **Copy:**
  - Header: "Jobs" + "Upload a PDF, watch it run, review what was extracted."
  - Live indicator: "Live · refreshes every N s", or "Reconnecting…" (warn) when the last poll failed.
  - Footer: "Showing N of M jobs" + "Clean up finished jobs…".
- **Mobile:** below 640 px, each job is a two-line card, and the detail panel moves below the list. No page-level horizontal scroll at 390 px.
- **Tests:** query by role/label. Pure logic is table-driven. The `Api` port is extended in `fakeApi()`.

## Review Focus

1. **The selected job disappears** (deleted, or filtered out by a chip or search). Expect the panel to fall back to the first visible job, or to say "Select a job", and never to show a stale or crashed panel. Test in Task 7.
2. **Some uploads in a multi-file batch fail.** The others still upload, each file shows its own result, and the strip resets only the files that succeeded. Test in Task 4.
3. **The detail panel's step runs or outputs fail to load,** for example because the job was deleted meanwhile. Expect an inline note, while the rest of the panel and the list keep working. Test in Task 6.
4. **The poll refreshes while an inline confirm or the model picker is open.** It must not close or reset it. Test in Task 5.
5. **A file that isn't a PDF is dropped** onto the strip. Expect it to be skipped with "Not a PDF" and not uploaded. Test in Task 4.

  app.get<{ Params: { id: string } }>('/jobs/:id/document', async (req, reply) => {
    if (!UUID.safeParse(req.params.id).success) return reply.code(404).send({ error: 'not found' });
    const doc = await app.deps.repo.getDocumentObject(req.params.id);
    if (!doc) return reply.code(404).send({ error: 'not found' });
    const body = await app.deps.store.get(doc.bucket, doc.key);

    const safeName = doc.filename.replace(/["\\\r\n]/g, '_');
    return reply
      .header('content-type', 'application/pdf')
      .header('content-disposition', `inline; filename="${safeName}"`)
      .header('x-content-type-options', 'nosniff')
      .header('cache-control', 'private, max-age=300')
      .send(body);
  });

```ts
import type { JobStatus, JobSummary, StepRun } from '@ih/shared';
import { statusGroup, type StatusGroup } from '../shell/derive.js';

export type Tone = 'neutral' | 'info' | 'warn' | 'alert' | 'danger' | 'ok';

const STATUS: Record<JobStatus, { label: string; tone: Tone }> = {
  queued: { label: 'Queued', tone: 'neutral' },
  running: { label: 'Running', tone: 'info' },
  awaiting_review: { label: 'Awaiting review', tone: 'warn' },
  needs_review: { label: 'Needs review', tone: 'alert' },
  failed: { label: 'Failed', tone: 'danger' },
  succeeded: { label: 'Succeeded', tone: 'ok' },
  rejected: { label: 'Rejected', tone: 'neutral' },
  cancelled: { label: 'Cancelled', tone: 'neutral' },
};

export const statusLabel = (s: JobStatus) => STATUS[s].label;
export const statusTone = (s: JobStatus) => STATUS[s].tone;

export type PrimaryAction = 'review' | 'view' | 'retry' | 'cancel' | null;
const PRIMARY: Record<JobStatus, PrimaryAction> = {
  queued: 'cancel', running: 'cancel', awaiting_review: 'review', needs_review: 'retry',
  failed: 'retry', succeeded: 'view', rejected: null, cancelled: 'retry',
};
/** The single most likely action for a job's status (UI handoff principle 1). */
export const primaryAction = (job: JobSummary): PrimaryAction => PRIMARY[job.status];

/** The second line under a job's file name. */
export function jobNote(job: JobSummary): { text: string; tone: 'muted' | 'warn' | 'danger' } {
  switch (job.status) {
    case 'queued': return { text: 'Waiting for a worker', tone: 'muted' };
    case 'running': return { text: 'Extracting…', tone: 'muted' };
    case 'awaiting_review': return { text: job.reviewReasons?.[0] ?? 'Waiting for a reviewer', tone: 'warn' };
    case 'needs_review': return { text: job.error ?? 'Needs an operator', tone: 'warn' };
    case 'failed': return { text: job.error ?? 'Failed', tone: 'danger' };
    case 'succeeded': return { text: job.test ? 'Test run · not published' : 'Published', tone: 'muted' };
    case 'rejected': return { text: job.reviewer ? `Rejected by ${job.reviewer}` : 'Rejected', tone: 'muted' };
    case 'cancelled': return { text: 'Cancelled by operator', tone: 'muted' };
  }
}

export type Chip = 'all' | StatusGroup;
export function inChip(job: JobSummary, chip: Chip): boolean {
  return chip === 'all' || statusGroup(job.status) === chip;
}
export function chipCounts(jobs: readonly JobSummary[]): Record<Chip, number> {
  const counts: Record<Chip, number> = { all: jobs.length, attention: 0, active: 0, done: 0 };
  for (const j of jobs) counts[statusGroup(j.status)]++;
  return counts;
}

export type StepState = 'done' | 'current' | 'wait' | 'fail' | 'todo';
const STEP_LABELS = ['Text & OCR', 'Sections', 'Extraction', 'Validation', 'Review & publish'] as const;
const STATE_TEXT: Record<StepState, string> = {
  done: 'Done', current: 'Running', wait: 'Waiting for you', fail: 'Stopped', todo: '',
};

/**
 * The 5-step progress list, derived from status + step runs (no stage tracking yet; A1 is
 * phase 2). Step runs prove text and sections were done; all runs succeeding proves extraction.
 */
export function progressSteps(job: JobSummary, runs: readonly StepRun[] | null) {
  const states = (done: number, last: StepState | null): StepState[] =>
    STEP_LABELS.map((_, i) => (i < done ? 'done' : i === done && last ? last : 'todo'));
  const ran = runs === null ? null : runs.length > 0;
  const extracted = runs !== null && runs.length > 0 && runs.every((r) => r.status === 'succeeded');
  let s: StepState[];
  switch (job.status) {
    case 'queued': s = states(0, null); break;
    case 'running': s = ran ? states(2, 'current') : states(0, 'current'); break;
    case 'awaiting_review': s = states(4, 'wait'); break;
    case 'succeeded': s = states(5, null); break;
    case 'rejected': s = states(4, 'fail'); break;
    case 'cancelled':
    case 'failed':
    case 'needs_review':
      if (ran === false || ran === null) {
        s = /section/i.test(job.error ?? '') ? states(1, 'fail') : states(0, 'fail');
      } else {
        s = extracted && job.status !== 'cancelled' ? states(3, 'fail') : states(2, 'fail');
      }
      break;
  }
  return STEP_LABELS.map((label, i) => ({ label, state: s[i]!, text: STATE_TEXT[s[i]!] }));
}

export function relativeTime(iso: string, now: number): string {
  const mins = Math.floor(Math.max(0, now - Date.parse(iso)) / 60_000);
  if (mins < 1) return 'Just now';
  if (mins < 60) return `${mins} min ago`;
  const hours = Math.floor(mins / 60);
  if (hours < 24) return `${hours} h ago`;
  const days = Math.floor(hours / 24);
  if (days === 1) return 'Yesterday';
  if (days <= 30) return `${days} days ago`;
  return new Date(iso).toLocaleDateString();
}

/** What ran (step runs), else what was requested (override), else the spec default. */
export function modelLabel(job: JobSummary): string {
  if (job.modelsUsed.length) return job.modelsUsed.join(', ');
  return job.modelOverride ?? 'Spec default';
}
```

The "runs not loaded yet" row (`runs === null`, awaiting_review) is covered because that status doesn't consult runs.
