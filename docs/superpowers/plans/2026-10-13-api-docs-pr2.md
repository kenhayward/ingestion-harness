# API docs PR 2: Pipeline routes (Documents, Jobs, Review & steps, Results, Models)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Document the 21 Pipeline routes with full descriptions and response schemas, adding
the shared helpers for binary downloads and multipart uploads.

**Architecture:** Same as PR 1: Fastify route `schema` blocks, documentation only (pass-through
compilers), converted by `apps/api/src/openapi/zod.ts`, checked by the docs sweep and the
response conformance hook. Response DTOs that are interfaces in `@ih/shared` become Zod schemas
with `z.infer` types of the same name.

**Tech Stack:** as PR 1.

**Spec:** [docs/design/api-docs.md](../../design/api-docs.md)

## Global Constraints

- No runtime behaviour change; handlers and error messages untouched.
- Every status code a handler can send is documented with its exact message.
- `additionalProperties: false` only where the Zod schema is `.strict()` (requests whose
  handlers reject unknown keys); everything else allows extra properties.
- Each route removed from `UNDOCUMENTED` in `apps/api/test/openapi.test.ts` in this PR;
  `npm run openapi` regenerates `docs/openapi.json`.

## Review Focus

1. Binary downloads (PDF, JPEG page, CSV/JSON output, ZIP archive) are described with their
   real content types and are not validated as JSON (conformance skips non-JSON bodies; a test
   in the existing suite downloads each one).
2. The multipart upload documents its field order (fields before the file) and every 4xx:
   400 (missing file, specId, unknown spec, draft without `test`, unknown model), 413, 415.
3. `GET /api/jobs/:id/review` returns the template: its schema must accept every template the
   tests use (conformance over `review.test.ts`).
4. Cleanup's two response shapes (dry run vs delete) are both documented.
5. A 502 from an unreachable store (`UnreachableStore` tests) is documented on every route that
   can send one.
